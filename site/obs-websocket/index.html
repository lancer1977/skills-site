# obs-websocket

Agentic control of the OBS Studio instance on arch-server (`192.168.0.173`,
same box `obs-websocket-mcp` runs on) via the `obs-websocket-mcp` MCP server
— repo: `github.com/lancer1977/obs-websocket-mcp` (private), cloned at
`~/code/obs-websocket-mcp` (canonical, tracks `main`) with active development
in a worktree at `~/worktrees/obs-websocket-mcp-v1` until the V1 PR merges.

## First: check the MCP tools are actually live

The `obs.*` tools (`obs.get_status`, `obs.list_scenes`, `obs.list_sources`,
`obs.set_current_scene`, `obs.set_source_enabled`, `obs.create_browser_source`,
`obs.start_stream`/`stop_stream`, `obs.start_record`/`stop_record`) come from
the registered MCP server, not from this skill directly. If they're not
showing up as available tools, the server isn't registered in this session —
see "Registering the MCP server" below.

## Credentials

Live in `~/.config/secrets/obs.env` (`OBS_HOST`, `OBS_PORT`, `OBS_PASSWORD`,
`OBS_TIMEOUT_SECONDS`, `OBS_ALLOW_WRITES`) — `OBS_HOST=127.0.0.1` since OBS
and the MCP server run on the same box (arch-server), which sidesteps any
firewall question entirely. **Never** hardcode these values or put
`OBS_PASSWORD` in a command string you're about to show/echo — always
`source` the file and reference `$OBS_PASSWORD` as a variable, same pattern
as the `seq`/`cloudflare-dns` skills.

## Hard rule: writes are off by default

`OBS_ALLOW_WRITES=false` is the default. Every mutating tool
(`set_current_scene`, `set_source_enabled`, `create_browser_source`,
`start_stream`, `stop_stream`, `start_record`, `stop_record`) raises
`UnauthorizedError` until it's flipped to `true` — this is a live A/V
control surface (it can put something on someone's actual stream), so
treat turning writes on as a real decision, not a default to reach for.
To enable: edit `OBS_ALLOW_WRITES=true` in `~/.config/secrets/obs.env`,
then re-run the registration command below (env vars are baked in at
registration time, not read live per-call).

## Registering the MCP server

Background/sandboxed Claude Code sessions cannot write their own MCP config
(`~/.claude/.config.json`) — the command silently no-ops even when it
reports success. Registration has to be run by the user directly:

```
source ~/.config/secrets/obs.env && claude mcp add obs-websocket-mcp -s user \
  -e PYTHONPATH=<path to obs-websocket-mcp checkout, e.g. ~/code/obs-websocket-mcp once merged> \
  -e OBS_HOST="$OBS_HOST" -e OBS_PORT="$OBS_PORT" -e OBS_PASSWORD="$OBS_PASSWORD" \
  -e OBS_TIMEOUT_SECONDS="$OBS_TIMEOUT_SECONDS" -e OBS_ALLOW_WRITES="$OBS_ALLOW_WRITES" \
  -- <path>/.venv/bin/python -m app.main
```

`claude mcp get obs-websocket-mcp` confirms it's actually registered — don't
trust the "Added stdio MCP server..." success message alone in a background
session, verify with `get`.

## Verified-live vs. mock-only (2026-08-19)

`obsws_python.ReqClient` has **no consistent kwarg-naming convention across
methods** — some take snake_case, some camelCase, some a bare positional
`name`. The connector's unit tests only ever ran against a mock I wrote
myself, which used the wrong convention for several methods; this wasn't
caught until testing against the real OBS instance. Confirmed correct via
`inspect.signature`/`getsource` on the installed package, not guessing:
- `get_current_program_scene()`, `set_current_program_scene(name)`,
  `get_scene_item_list(name)` — bare positional `name`.
- `set_scene_item_enabled(scene_name, item_id, enabled)` — snake_case.
- `create_input(sceneName, inputName, inputKind, inputSettings, sceneItemEnabled)`
  — camelCase.

**Live-verified end-to-end** (against real OBS 32.2.1, websocket 5.7.4):
`get_status`, `list_scenes`, `list_sources`, `create_browser_source`.
**Still mock-only, not yet exercised against real OBS**: `set_current_scene`,
`set_source_enabled`, `start_stream`/`stop_stream`, `start_record`/`stop_record`.
If any of these misbehave, check the actual installed `obsws_python`
signature first (`python -c "import obsws_python as o, inspect;
print(inspect.signature(o.ReqClient.<method>))"`) before assuming the bug is
elsewhere — this library's inconsistency is the most likely culprit.

## Adding chop-it (or any URL) as a test browser source

Once writes are enabled and the server is registered:
`obs.create_browser_source` with `scene_name`, `source_name`, `url` (plus
optional `width`/`height`, default 1920x1080). See
[[project_chop_it_status_202608]] for the live chop-it HLS test URL and a
known caveat about its manifest-replacement behavior in OBS Media/Browser
sources.
